TouchID pin test v2

Two-mode pogo pin survey · 100 Ω load ·

Why this rerun exists. The first load test collapsed J11-1/2/3 from 3.466 V down to 1.031 / 0.596 / 0.526 V, implying 236–559 Ω of source resistance — far too high for a battery rail. The keyboard's lights also changed under load. Since the keyboard's web settings can reassign these pins between switch module and knob module, the goal now is to measure both modes and see what moves.

Meter settings

  • DC volts (V⎓ / DCV) — not V∼. Lowest range above 3.5 V, ideally 4 V or 6 V for 1 mV resolution.
  • Continuity (beep) — for gnd and tied_to checks. Keyboard off and unplugged.
  • Ω — verify the resistor is 100, not 10 k, before every session.
  • Never A / mA across a rail.

100 Ω bands: brown-black-brown-gold. 10 kΩ: brown-black-orange-gold.

Ground-path control test — do this first, every session. With the load running on J11-1, move the meter's black probe from the breadboard − rail to the USB-C shell. If the reading jumps up toward 3.4 V, your J4-5 ground contact was the resistance and the whole run is invalid. If it stays near the loaded value, the drop is real and on the keyboard side. Record the result in the notes field.

Full procedure

Before you start

  1. Meter to Ω. Probe the resistor off-board. Confirm ~100 Ω. Switch to DC volts.
  2. Set the keyboard's web settings to the mode you are about to test. Write which one down — mixing up the two tables ruins the comparison.
  3. Build the breadboard before anything touches the keyboard.

Breadboard layout

  • 100 Ω resistor: one leg in 10a, other leg into the − rail above column 10.
  • Jumper 1: hole 10e → the pin under test.
  • Jumper 2: − rail (~column 8) → J4-5.
  • Meter red probe: 10c. Meter black probe: − rail (~column 2).

Holes 10a–10e are one node, so the resistor, jumper 1 and the red probe all meet there. The − rail is only ground because jumper 2 makes it so. Rows f–j and the bottom rails stay empty.

Phase 1 — continuity (keyboard OFF, unplugged)

  1. Ground pins. One probe on the USB-C metal shell, touch each pin. Beep = ground. Record yes/no on every pin — a blank means "not tested", not "no".
  2. Tied pins. Triangular sweep: fix on J4-1, sweep J4-2→J11-4; fix on J4-2, sweep J4-3→J11-4; and so on to J11-3↔J11-4. 45 checks. Only record a pair when it beeps.
  3. Settle the J11 question. Do J11-1, J11-2 and J11-3 beep to each other? This was never confirmed and the first load test suggests they may not be one node.

Phase 2 — voltage survey (keyboard ON)

DC volts. Black probe stays on ground; red probe touches each pin. 0.00 is a valid result — record it.

  • v_wired — USB in, tap a key first
  • v_wireless — cable out, BLE/2.4G, tap a key
  • v_sleep1_lightoff — backlight has dropped, keyboard untouched
  • v_sleep2_deep — idle 6+ minutes, don't touch, then measure
  • v_off — power switch off; anything live here is wired straight to the battery

Interpreting: 0.00 ground/inactive · ~3.3 logic high or 3.3 V supply · 3.5–4.2 battery rail · ~5 USB passthrough · drifting 0.1–0.9 floating.

Phase 3 — 100 Ω load test

Only pins reading a steady ≥3.3 V in the wireless sweep.

  1. Keyboard on, wireless, awake.
  2. Jumper 2 to J4-5 first. Ground before power, always.
  3. Jumper 1 to the pin under test.
  4. Resistor out of the board — read and record the unloaded value. No current flows, so contact quality can't affect this number.
  5. Resistor in — read within ~10 s and record as v_loaded.
  6. Re-seat your grip and repeat 4–5 times. Keep the highest reading — contact resistance can only pull it down, never up.
  7. Run the ground-path control test described above.
  8. Jumper 1 off first, then jumper 2.

Watch the keyboard while the load is on. Lights changing, the module mode switching, or anything else visible is data — put it in the notes column.

Phase 4 — mode comparison

  1. Complete Phases 1–3 fully in one mode.
  2. Change the mode in the keyboard's web settings. Power-cycle the keyboard if the setting needs it.
  3. Repeat Phases 1–3 without moving the breadboard.
  4. Read the comparison table. Pins that shift between modes are firmware-controlled and are the ones our module can potentially use.

What we're hoping to find: a mode in which one of the J11 pins presents a genuinely low source resistance, or a detect scheme we can imitate so the keyboard powers our module the way it powers the knob.

Safety

  • Probe one pin at a time. Bridging two pins can short vbat to ground.
  • Hold jumper wires by the insulation, never two bare tips at once.
  • 3.4 V at 35 mA is harmless to you — the risk is to the keyboard, not to your hand.
